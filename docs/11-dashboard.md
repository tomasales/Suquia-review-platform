# Dashboard

## Objetivo

El Dashboard debe responder de forma simple:

- ¿Qué está pasando?
- ¿Qué tengo que mirar?

## Decisiones tomadas

No queremos:

- métricas de productividad;
- gráficos;
- porcentajes;
- una pantalla de project management compleja.

## Elementos conceptuales

- Acción principal: **Subir entrega**.
- Entregas para revisar.
- Entregas recientes.
- Resumen de estado por entrega.
- Bloque pequeño: **Lo más marcado en las últimas reviews**.
- Journal reciente.

## Reglas de negocio

- El Dashboard debe priorizar acción y claridad.
- El bloque de IA debe ser pequeño y descriptivo.
- Ese bloque solo resume feedback reciente de Tomi; no genera Guidelines ni conclusiones sobre piezas nuevas.
- Cuando sea posible, los puntos resumidos deben poder vincularse a su feedback fuente.
- El indicador de Drive vive en la navegación persistente, no como bloque del Dashboard.
- Las entregas deben mostrar un resumen útil, por ejemplo cantidad de piezas OK y piezas que necesitan cambios.
